# 提交说明（复赛）— 卡车司机找货决策 Agent

## 一、总体思路
**LLM 把偏好编译成结构化约束，确定性代码守红线+算账+选单，少量未知偏好交带状态的 LLM 守护层。**
核心范式：确定性管已知、LLM 管未知、经济学管取舍、介入深度与不确定性成正比。

每步决策仅 0~2 个 LLM 触点：
1. **偏好编译**（整月一次，按偏好原文签名缓存）：把 `preferences` 原文编译成 `machine_ir`；
2. **守护层 Council**（仅当存在编译覆盖不了的偏好时才触发）：带逐月台账复核候选风险，调分/否决；
偏好全部可结构化的司机（绝大多数）全程零守护调用，走纯确定性快车道（token 极低、零方差）。

## 二、合规声明（关键）
**`agent/*.py` 内零偏好常量**：没有任何样例地名 / 品类 / 司机号 / 时段 / 金额 / 阈值的硬编码。一切偏好语义（作息时段、品类配额、所属月份、长途阈值与上限、区域规避等）均由大模型在运行时从 `get_driver_status` 的 `preferences` 原文编译得到；代码只做「按字段取值 / 按算子比较 / 按月或按日计数 / 时段静止判定」这类与具体规则无关的通用求值。
- 编译提示词中的作息顺延规则用**符号化表述**（窗 A 至 B、晚 N 小时则新窗 (A+N) 至 B），数字示例为与任何已知司机都不吻合的虚构值；不含公开样例的具体小时数。
- 品类名匹配用**运行时观测词表对齐**（query_cargo 返回累积），非内置词表。
- 随包附 `check_compliance.sh`：grep `agent/*.py` 确认无偏好常量（含初赛与复赛样例词）。
- 已在多个**未出现在样例中的合成司机**上本地验证泛化（含「每日上限」这类 schema 无对应槽位的偏好——被正确识别为非月度周期、交守护层处理，而非错编进月度槽位）。

## 三、架构（单文件 `demo/agent/model_decision_service.py`）

```
L1 编译层(LLM, 整月一次):
   preferences 原文 → machine_ir{rest_windows(含 weekday/weekend 区分)/long_haul_limits/
   cargo_targets(含跨月欠额结转)/cargo_max_limits/region_avoid/origin_avoid/
   unknown_constraints(逃逸通道,绝不静默丢弃)}
   + temperature=0 单次编译(控制单步延迟以守 4 小时总时长上限) + 每条约束附 source_quote
L1.5 编译后确定性 audit:
   九项合法性检查 + rest 五条件(缺时间锚点不按猜测执行) + 周期一致性(日/周周期严禁入月度槽)
   + avoid×配额品类冲突剥离 + 幻觉/重复清洗 + semantic-family 去重 → 全部降级而非删除
L2 状态台账(确定性):
   逐月品类计数 / 干线时长列表(动态阈值长途计数) / 每日接单数 / 时钟小时占用 /
   跨月目标记忆(makeup 结转) / 观测货源热点+品类词表
L3 市场感知(确定性):
   query_cargo(k=220) → 查货后重取 status 全量重建候选(消除时钟盲区) →
   候选弱或月末配额欠额时定向扩查
L4 决策核心(确定性 argmax, 全量候选):
   硬 veto(作息窗原子区间/长途上限/品类月上限/每日接单上限/区域避) →
   score = 有效时薪 + 配额次梯度影子价格 + 终点流动性 − 长途/超长占用软罚 + 守护调分(限幅±800) →
   取最高分(>0 接单, 否则受限迁移/等待, 三层作息防线最高优先级)
L5 残差守护(LLM, 条件触发):
   仅 unknown_constraints 非空时调用; 审【按确定性 score 排序的 top-10】(与 argmax 对齐);
   带逐月台账+最近动作+偏好原文; 输出 hard_avoid(须带依据,缺则降级)/soft_avoid(风险分级)/
   must_wait(钳位); 权限有界——只能调分/否决,不能凭空指定动作, 不能覆盖确定性作息休息
```

## 四、关键设计点
- **作息三层防线**：进入休息窗立即睡到窗尾（不查货）/ 候选完成区间与休息窗重叠即弃（跨午夜归属前一日、weekday/weekend 分别归属）/ 无正分候选时距窗近则直接睡穿。
- **配额经济化**：欠额品类按"边际罚款×紧迫度"折成分数加成顺路补，绝不为配额封杀其他单或强制迁移（强制履约对未知司机有副作用）。跨月欠额由编译标记 + 代码按台账 shortfall 合成补欠目标。
- **错编防御**：audit 周期/幻觉/冲突校验（九项合法性 + 周期一致性 + avoid×配额冲突剥离）+ unknown 逃逸——任何不确定的约束降级交守护层，绝不带病硬执行（"错编比漏编更危险"）。
- **每日上限确定性化**："每天最多 N 单"编译进 daily_order_caps，按日计数(订单起始日，与评分同口径)确定性 veto 第 N+1 单——精确守住、不再依赖守护层每步复核（守护层仅作未知约束的兜底）。
- **时长型作息确定性化**："连续休息≥N小时"(只给时长不给钟点)编成同一日历日内的 N 小时窗(00:00-N点)，满足"单日最长连续休息≥N小时"口径且不过度休息（治"占位窗被执行成整天休息→颗粒无收"）。
- **整天歇车确定性预留**："每月至少 N 整天不出车"编进 off_day_requirements，月末逼近(剩余天数≤还需天数)时确定性强制整天歇(当日活动=0)，不再 punt 给守护层(它无法预留未来整天)。
- **决策绝不抛异常**：任何环节失败兜底为安全 wait，单步不让司机整月归零。
- **通用接单规则经济化**：品类/地区/赴装空驶/干线时长等逐单偏好统一编译为 `order_rules`；
  明确罚款先进入调价后净收益与净时薪，绝对禁令才 hard veto。累计上限与最低配额冲突会被 audit 剥离，
  防止把“超额才罚”误读成“每单都罚”、或把“必须接满”反向编成禁接。
- **日历例外覆盖基础窗**：周末/工作日专用作息窗覆盖与其重叠的 all-days 基础窗，避免“周末晚休”
  被基础窗口取并集吞掉，既守偏好又释放合法经营时间。
- **配速驱动履约**：最低配额落后线性进度时提前提高影子价格并定向扩查，不再把补缺压力拖到月末。
- **末期欠额紧迫度**：仅当剩余天数接近“欠额+安全缓冲”时，进一步提高目标货的边际价值；
  月初与正常进度保持原评分，避免为了低价值配额单牺牲整月净收益。
- **周末晚休审计纠偏**：若模型把“周末晚两个小时再休息”误解为开始和结束一起顺延，
  编译后 audit 会保留周末开始时间延后，但把结束时间拉回基础休息窗结束钟点，防隐藏集作息误罚。
- **单月目标月份审计**：若某个配额目标的依据原文只明确提到一个月份，而模型把目标挂到其他月份，
  编译后 audit 会把 month 修回原文月份；同时复合句同时含多个月份时不猜测，避免误伤补欠语义。
- **冷市场短等待探针**：当当前候选没有正收益且不临近休息窗时，前两次只短等 60 分钟后重扫，
  再逐步退避到 90/120 分钟；若临近休息窗仍直接睡穿。这样能在货源刷新较快的区域减少白天长睡，
  同时不放松作息红线。

## 五、运行约束
单司机 token 远低于 500 万上限（多数司机走零守护快车道，token 极低）；单步决策远低于 2 分钟；`enable_thinking=False` + 低频 LLM 调用控制总墙钟。
