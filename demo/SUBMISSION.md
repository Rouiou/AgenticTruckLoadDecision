# 提交说明（复赛）— 决策 Agent

## 一、总体思路
本 agent 是一个 **Agent Harness**：大模型(Qwen3.5-Flash)负责【理解模糊偏好文本】，确定性 Python 代码负责【计算、护栏、整月义务执行】。核心范式：**大模型把偏好编译成结构化规则(IR)，代码确定性执行**——稳、省 token、可人工复核。

## 二、合规声明（关键）
**agent/\*.py 内零偏好常量**：没有任何样例地名 / 品类 / 司机号 / 时段 / 金额 / 阈值的硬编码。一切偏好语义（禁某品类、作息时段、品类配额单数、所属月份、长途时长阈值与月度上限等）均由大模型在运行时从 `get_driver_status` 返回的 `preferences` 原文编译得到；代码只做「按字段取值 / 按算子比较 / 按月计数」这类与具体规则无关的通用求值。
- 随包附 `check_compliance.sh`：grep `agent/*.py` 确认无偏好常量（含初赛与复赛样例词）。
- 偏好规则随司机变化，本 agent 对偏好文本泛化——已在多个**未出现在样例中的合成司机**上本地验证：品类配额、跨月欠额结转、月度单数上限、禁品类、固定作息均正确履约。

## 三、模块清单（`demo/agent/`）
| 文件 | 职责 |
|---|---|
| `model_decision_service.py` | 编排入口 `decide()`：串起各模块产出一个动作；**永不抛异常**（抛了该司机整月归零）。 |
| `compiler.py` | **LLM 编译器**：逐条把偏好原文编译成 IR——`order_filters`(禁接) / `rest_windows`(作息,区分钟点型/连续时长型) / `off_days_required`(整休) / `category_quotas`(品类月度配额) / `monthly_count_caps`(月度单数上限)。逐条编译 + 哈希缓存 + 全空重试。 |
| `checker.py` | 确定性质检：按 IR 标注候选是否违规、作息时段判定、否决退回大模型。 |
| `planner.py` | 低频日度规划：休息块 / 整休日 / 日期到点任务 / 区域累计义务。 |
| `memory.py` | 跨步事实台账：按月按品类计数、整休天计数、区域到访日等（**只记事实，不判偏好**）。 |
| `tools.py` | 纯函数：地理/时间估算（**真实完成时刻=空驶+等装货窗+干线**）、可行性预筛、ROI、候选准备。 |
| `prompts.py` / `llm.py` / `guardrails.py` | 提示词 / 稳健模型调用(关 thinking + 3 重试) / 动作校验与兜底。 |

## 四、复赛适配（相对初赛新增的能力）
复赛偏好新增两类，已实现确定性履约（全部经大模型编译、代码零硬编码）：
1. **品类月度配额**（某月必须主动接满 N 单某品类，含跨月欠额结转）：`memory` 按月按品类计数；`model_decision_service` 进度感知履约——领先则候选里优先该品类、落后则每天广查抓该品类货（就近接、省里程，每品类每天最多广查一次）、临月末提级硬接。
2. **月度单数上限**（每月超 N 小时长途最多 M 单）：`memory` 按月计数；达上限后该类候选标违规、不再接；配额履约也优先挑非长途单以避免与上限对撞。
3. **稀缺品类货源密集区探测**（治"配额品类在司机周边极稀缺、原地查不到"）：`memory` 按地理网格累计该品类货源出现频次（坐标来自 `query_cargo` 客观返回）；当【按本月已凑速率外推凑不满】且本地+广查都查不到时，向历史高频密集区发起 `query_cargo` 探测（接口支持查询任意坐标周边在线货源），确认此刻真有干净货（不违规、不跨休息时段、本月内可完成，且按司机当前真实位置重算空驶/完成时刻）才接单迁移过去蹲守。配速判别（纯算术）保证"本地能从容凑满的司机绝不提前动用大空驶"；每天每品类最多探测一次。频次/坐标/品类全部来自运行时观测与 LLM 编译，零偏好常量。

## 五、运行契约
评测侧用统一 `server/` 加载本 `demo/agent/`，构造 `ModelDecisionService(port)` 并逐步调用 `.decide(driver_id)`，与赛题包契约一致，无需额外配置。`check_compliance.sh` 为自检脚本，非运行依赖。
